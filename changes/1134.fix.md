An `llmconfig.yml` with only Enterprise LiteLLM gateways and no static models now validates, starts, and serves chat; a configuration with neither a static model nor a gateway still reports a clear validation error, and gateway connection failures stay distinct from schema errors. `atlas list-models --json` now always emits a `litellm_gateways` array next to `models` and exits 1 only when neither source is configured, and child-run (`atlas_launch`) discovery reports that it needs a statically configured model instead of a generic "no models" on gateway-only deployments.
