Docker Compose no longer requires credentials for storage backends you do not use: bundled MinIO and PostgreSQL moved to opt-in Compose files (`docker-compose.minio.yml`, `docker-compose.postgres.yml`), external S3 needs no `MINIO_ROOT_PASSWORD`, DuckDB needs no `POSTGRES_PASSWORD`, and the bundled MinIO reuses `S3_ACCESS_KEY`/`S3_SECRET_KEY` as its root credentials. The bundled MinIO also became startable at all: it now mounts the image-declared `/bitnami/minio/data` path and uses a working readiness probe.

  Operators upgrading a Compose stack: the old variables are no longer read and Compose fails configuration until the new ones are set — add `-f docker-compose.minio.yml` and/or `-f docker-compose.postgres.yml`, set `S3_ENDPOINT=http://minio:9000` plus `S3_ACCESS_KEY`/`S3_SECRET_KEY`. Stacks from before v0.8.0 shipped `minioadmin`/`minioadmin` with files under `./data/minio`; v0.8.0-era `minio-data` volumes are empty and can be removed with `docker volume rm <project>_minio-data` (never `compose down -v`, which also deletes chat history and MCP tokens).
