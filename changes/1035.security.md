HTTP RAG queries now check every requested corpus against its own data classifications at query time, so a stale selection, direct request or agent `atlas_search` call cannot reach a corpus discovery hides; a batch with any disallowed or unlisted corpus is refused before anything is sent. Behavior change: in a classified session the backend's discovery must list every queried corpus for that user, and queries fail closed while discovery is unavailable (`DATA_SOURCE_UNVERIFIED`) or does not list the corpus (`DATA_SOURCE_NOT_LISTED`).
