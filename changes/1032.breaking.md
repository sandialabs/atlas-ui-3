Models, MCP servers and RAG sources (and individual RAG corpora) now declare the data classifications they may receive with `allowed_data_classifications`, and the server refuses any chat turn whose selected compliance level is not listed by the model, the servers behind its tools, or its data sources; an undefined level is refused too. Components with no declaration are unavailable in classified sessions, `allowed_with` no longer grants access across levels (personas must now match the selected level exactly), and query-time RAG enforcement follows the selected level, falling back to the model's classifications when none is selected. A legacy `compliance_level` is still read as a one-element list; see docs/admin/compliance.md for migration.
