Backend tests no longer read any `.env` file: the test harness disables dotenv loading (python-dotenv's `PYTHON_DOTENV_DISABLED`) before the app is imported, Atlas's own `.env` reads honor the same switch, and `DEBUG_MODE` defaults explicitly, so results no longer depend on a checkout-local `.env` or on import order. Runtime `.env` handling is unchanged unless `PYTHON_DOTENV_DISABLED` is set; a process that sets it now also skips the settings `.env` source (with a one-time warning), consistent with `load_dotenv`.
