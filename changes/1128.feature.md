With Redis configured, `MAX_CONCURRENT_RUNS_PER_USER` and the one-run-per-conversation rule now hold across all API replicas: each run is claimed atomically in Redis before it starts, refused claims hold no slot, and a crashed replica's slots free themselves within 30 seconds. The configured cap also now applies to agent-runs API traffic on a replica that has not yet served a WebSocket connection (it previously fell back to 5). Behavior change: when Redis is configured but unreachable, new runs and WebSocket turns are refused (`run_coordination_unavailable`, or HTTP 503 from the agent-runs API) instead of starting untracked; runs already executing continue.
