Docker Compose no longer requires credentials for storage backends you do not use: bundled MinIO and PostgreSQL moved to opt-in Compose files (`docker-compose.minio.yml`, `docker-compose.postgres.yml`), external S3 needs no `MINIO_ROOT_PASSWORD`, DuckDB needs no `POSTGRES_PASSWORD`, and the bundled MinIO reuses `S3_ACCESS_KEY`/`S3_SECRET_KEY` as its root credentials.

  Operators upgrading a single-file stack: the old variables are no longer read and Compose fails configuration until the new ones are set — add `-f docker-compose.minio.yml` and/or `-f docker-compose.postgres.yml`, set `S3_ENDPOINT=http://minio:9000` plus `S3_ACCESS_KEY`/`S3_SECRET_KEY` (old `MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD` values keep an existing `minio-data` volume; the server now stores data under `/bitnami/minio/data`). The bundled PostgreSQL file supplies the container's `CHAT_HISTORY_DB_URL` from `POSTGRES_PASSWORD`.
