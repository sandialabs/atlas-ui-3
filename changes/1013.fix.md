MCP sessions are now released on the runtime tool manager that actually serves chat when a run finishes, a WebSocket disconnects, or a conversation is restored, instead of an unused import-time manager — so per-conversation MCP sessions and cached per-user clients no longer leak until restart. The removed public exports `atlas.modules.mcp_tools.mcp_tool_manager` and `atlas.modules.llm.llm_caller` no longer exist; use `app_factory.get_mcp_manager()` and `app_factory.get_llm_caller()` instead. Note: a conversation's MCP sessions are now actually released when its last run finishes, so stateful MCP servers start each turn of a conversation with fresh sessions; state that must survive across turns belongs in the server's own durable store.
