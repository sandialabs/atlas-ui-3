Fixed compliance level filtering: the compliance levels file is now actually loaded from `config/` or the package defaults (previously the header selector never appeared), and the selected level now consistently applies its allowlist to tools, prompts, personas, data sources and the model -- hidden selections are deselected and never sent, and a model outside the level is switched or flagged. Upgrade note: level definitions now take effect, so a deployment that tags resources with level names not in the bundled defaults (for example "CUI") must define them in `config/compliance-levels.json`; undefined names are treated as unset.
