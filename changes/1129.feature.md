Staging deployment for Kubernetes and OpenShift (`deploy/kubernetes/`) with three API replicas on shared Redis, PostgreSQL and S3. It has no affinity or sticky sessions and includes probes and resource limits. `staging.sh` and `validate_replicas.py` check that each replica serves traffic, that authentication holds and that a session resumes on a different replica. The image now ships Alembic, and `python -m atlas.modules.chat_history.schema_migration` runs migrations once under a PostgreSQL advisory lock, so replicas no longer race `create_all` on an empty database. See `docs/admin/kubernetes-staging.md`.

Per-replica coordination observability for multi-replica deployments: `/admin/coordination` (JSON) and `/admin/coordination/metrics` (Prometheus text) report run counts by state, interrupted vs failed outcomes and Redis/PostgreSQL status, every coordination event is a `[COORD]` log line naming the replica, `/api/health` now probes the chat-history database live, and a replica that shuts down marks its live runs failed with `end_reason: replica_shutdown` instead of leaving them cancelled or silently lost. Failure-injection scripts for pod deletion, Redis/PostgreSQL outages and rollouts are in `scripts/failure-injection/` (see docs/admin/multi-replica-observability.md).
