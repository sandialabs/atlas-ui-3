Sessions can now be shared across API replicas with `SESSION_REPOSITORY_TYPE=redis` and `REDIS_URL`. A client that reconnects to any replica resumes its session (history, files, conversation and classification bindings), stale writes are refused rather than overwriting newer state, and startup fails instead of falling back when Redis is unreachable. Redis connections are bounded per process (`REDIS_MAX_CONNECTIONS` and timeouts), `/api/health` reports session-store status, and tracked agent runs stay process-local for now; see the session-store guide.
